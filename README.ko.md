# ani — Agent Negative Index

**[English](README.md)** · 한국어

**"아니 그게 아니라" 프로토콜 · 부정 피드백을 해소하는 루프**

`ani`에는 뜻이 두 겹 있다.

- 한국어 **아니**. **"아니 그게 아니라…"** — 코딩 에이전트를 쓰다 보면 결국 하게 되는 그 말이다.
- **Agent Negative Index** — 에이전트가 받은 negative의 색인. "아니 그게 아니라" 순간을 하나도
  빠짐없이 붙잡아 검증된 패턴으로 컴파일해 두고, 같은 실수가 반복되기 전에 먼저 들춰 본다.
  파이썬의 음수 인덱싱 `history[-1]`처럼, 마지막 실패에서 거꾸로 읽어 앞으로 나아간다는 뜻이다.

ani는 그 순간을 진지하게 다루는 파일 기반 프로토콜이다. 특정 에이전트에 매이지 않는다. 교정을
붙잡아 검증된 성공패턴으로 컴파일하고, 그 실패를 만들어낸 컨텍스트는 버려도 되는 물건으로 만든다.
파일을 읽고 쓸 줄 알면 무엇이든 ani를 말할 수 있다.

## 30초 요약

교정은 에이전트가 받을 수 있는 가장 값진 신호다. **오해한 의도, 진짜 의도, 그리고 고치는 방법**이
실패한 바로 그 자리에서 한 문장에 담겨 건네진다. "맞다"가 무엇이었는지 아는 유일한 사람이 직접 쓴
버그 리포트인 셈이다.

그런데 어느 에이전트든 이걸 버린다. 세션이 끝나고 트랜스크립트가 화면 밖으로 밀려나면, 다음 세션은
같은 실수를 되풀이한다. 컨텍스트 윈도우를 아무리 키워도 소용없다. 애초에 아무것도 적히지 않았으니까.

ani는 여기에 세 가지로 대응한다.

1. **붙잡는다.** 실패패턴 `F`로 — 의도, 오독, 교정, 그리고 원문 발췌까지. 컨텍스트 윈도우 바깥의
   파일에 남긴다.
2. **컴파일한다.** `F`를 검증 조건이 필수인 성공패턴 `S`로 바꾼다. 신뢰 사다리를 따라서: 증거가
   쌓이면 자동으로 *잠정(provisional)* 등급까지 올라가 즉시 쓸 수 있고, 사람이 도장을 찍으면
   *활성(active)*이 된다. 사람은 게이트키퍼가 아니라 감사자다.
3. **컨텍스트를 놓아준다.** 실패는 이미 세션 밖에 살아 있으니, 오염된 컨텍스트를 붙들고 갈 이유가
   없다. ani는 되감기나 새 세션을 권한다.

## 설치

검증된 경로 셋.

### 1. Claude Code 플러그인 (권장)

```
/plugin marketplace add <owner>/ani
/plugin install ani
```

스킬과 hook이 함께 켜진다. 플러그인으로 설치하면 스킬 이름에 `plugin-name:skill-name` 네임스페이스가
붙어서 실제로 입력하는 명령은 `/ani:ani`가 된다 (`/ani:ani ok F-…`, `/ani:ani bootstrap`). 스킬
디렉터리에 직접 복사했다면 그냥 `/ani`다. **이 문서는 프로토콜의 짧은 형태인 `/ani`로 통일해서
쓴다.**

### 2. 스킬 복사

`skills/ani/`를 에이전트의 스킬 디렉터리에 복사한다. Tier 0은 순수 마크다운이고 그 자체로 완결이다.
포기하는 건 결정론적 hook 하나뿐인데, 그건
[`adapters/claude-code.md`](skills/ani/references/adapters/claude-code.md)가 따로 다룬다.

### 3. AGENTS.md 스니펫 붙여넣기

스킬 시스템이 없는 에이전트라면
[`adapters/agents-md.md`](skills/ani/references/adapters/agents-md.md)의 블록을 `AGENTS.md`에
붙여넣으면 된다. 그 밖의 환경은 [`generic.md`](skills/ani/references/adapters/generic.md)를 보라.
어댑터는 검증을 마친 하네스부터 하나씩 늘려 간다 — [기여를 환영한다](CONTRIBUTING.md).

**첫날부터 저장소가 텅 비어 있지는 않다.** `/ani bootstrap [--days N]`은 지난 Claude Code
트랜스크립트에서 과거 교정을 캐내 군집으로 묶고, 지나고 나서야 보이는 것들까지 반영해 점수를 매긴
다음, 후보를 한 번에 승인하게 해준다
([`adapters/bootstrap.md`](skills/ani/references/adapters/bootstrap.md)).

## 무엇이 파일로 남는가

ani가 아는 것은 전부 마크다운이다. 저장소는 둘, 레이아웃은 하나다.

```
~/.ani/                           # 전역 (기본값, 항상 있다): 내 교정들이 사는 곳.
├── INDEX.md                      #   repo를 옮겨 다녀도 따라온다
├── patterns/                     #   — 경로는 global_store로 바꿀 수 있다
│   ├── F-20260828-a1b2c3d4.md    # 실패패턴
│   └── S-dark-mode-tokens.md     # 성공패턴
└── config.md                     # 선택적 오버라이드

<project>/.ani/                   # 프로젝트 (옵트인 오버레이): repo 안에서만 쓰는 패턴.
                                  #   commit하고, 공유하고, PR 리뷰를 거쳐 승격한다
```

**이 repo의** 파일과 관례에 관한 교정은 오버레이가 있으면 그쪽으로 간다. **내가 일하는 방식**에 관한
교정은 전역 저장소로 가고, 애매한 것도 전역으로 간다 — 개인 지식이 팀 repo로 새는 쪽이 훨씬 비싼
실수라서다. 검색은 두 저장소를 모두 훑되 프로젝트가 먼저다.

실제 사고 하나. 사용자는 다크모드에서 **배경**을 바꿔 달라고 했는데, 에이전트는 **글자** 색을 바꿨다.
그것도 토큰이 아니라 컴포넌트 안에서.

**실패패턴** `<store>/patterns/F-20260828-a1b2c3d4.md` (일부 생략):

```markdown
---
id: F-20260828-a1b2c3d4
status: compiled
date: 2026-08-28
trigger_quote: "아니 그게 아니라 배경색만 바꾸라고"
keywords: [dark-mode, css, background, tokens]
---

## Intent
다크모드 카드 표면을 더 어둡게. 배경만이다. 글자색은 멀쩡했다.

## Misreading
에이전트는 "어둡게"를 "내용을 흐리게"로 읽고 `Card.module.css`의 `.card`에서
`color`를 고쳤다 — 속성도 틀렸고 계층도 틀렸다. 모든 표면이 읽어 가는 토큰
대신 컴포넌트 하나를 덮어썼다.

## Correction
그 편집을 되돌리고, `src/styles/tokens.css`의 `[data-theme="dark"]` 블록에서
`--surface-bg`를 `#1e1e1e`에서 `#141414`로 바꿨다.

## Excerpt
> User: 다크모드에서 카드가 너무 밝아. 좀 더 어둡게 해줘.
> Agent: Card.module.css에서 `.card { color: #8b8b8b }` 로 조정했습니다.
> User: 아니 그게 아니라 배경색만 바꾸라고. 글자색은 건드리지 마.
```

`## Excerpt`는 필수이고, 그것만으로 완결이어야 한다 — 트랜스크립트를 볼 수 없는 사람도 이 발췌만
읽고 실패를 재구성할 수 있어야 한다.

**컴파일된 성공패턴** `<store>/patterns/S-dark-mode-tokens.md` (일부 생략):

```markdown
---
id: S-dark-mode-tokens
status: active
compiled_from: [F-20260828-a1b2c3d4]
date_compiled: 2026-08-28
keywords: [dark-mode, css, background, tokens]
scope: project
summary: 다크모드에서 뭔가를 밝게/어둡게 해달라는 요청이 올 때 쓴다
---

## Situation
`src/styles/tokens.css`의 custom property로 테마를 입힌 UI에서, 밝기 표현
("더 어둡게", "너무 밝아")으로 들어온 색 변경 요청.

## Action
1. 어떤 **속성**을 말하는 것인지 되짚어 확정한다 — 밝기 표현은 속성을 지목하지 않는다.
2. 이미 그 값을 몰고 있는 토큰을 찾아(`rg "--surface-" src/styles/tokens.css`)
   해당 테마 블록에서 바꾼다. 컴포넌트 파일은 절대 건드리지 않는다.

## Verification
- method: `git diff --name-only`
  target: 작업 트리
  expected: `src/styles/tokens.css` 하나만 나온다
  evidence: 이번 턴의 명령 출력
  on_failure: 컴포넌트 단위 편집을 되돌리고 토큰에서 다시 한다

## Counter-examples
- 특정 요소에 hex 값을 못 박은 요청에는 쓰지 않는다 — 그건 문자 그대로의 지시다.
```

**그리고 에이전트 컨텍스트에 남는 INDEX 한 줄**:

```markdown
| id | status | scope | keywords | summary | updated |
| --- | --- | --- | --- | --- | --- |
| S-dark-mode-tokens | active | project | dark-mode, css, background | 다크모드에서 뭔가를 밝게/어둡게 해달라는 요청이 올 때 쓴다 | 2026-08-28 |
```

frontmatter가 진실의 원천이고, `INDEX.md`는 언제든 다시 만들 수 있는 캐시다. 저장소당 60행 / 6KB
예산 안에서 움직인다 — 게다가 두 저장소가 세션 시작 시 **하나의** 6KB 주입을 나눠 쓰므로, 두 번째
계층을 켠다고 상시 컨텍스트 비용이 늘지 않는다. 카탈로그를 통째로 상주시키고 선제 매칭을 공짜로
만드는 것이 바로 이 예산이다. 필드 이름은 영어지만 값은 어떤 언어로 써도 된다. 규범 스펙:
[`schemas.md`](skills/ani/references/schemas.md).

## 어떻게 돌아가는가

탐지는 의미로 한다. hook이 있든 없든 루프는 돈다.

```
사용자가 "아니 그게 아니라"라는 뜻의 말을 한다
        │
   [1] RESTATE  ─ 무엇보다 먼저, 진짜 의도를 한 줄로 되짚어 말한다.
        │         확인 질문은 많아야 하나.
   [2] SEARCH   ─ 두 INDEX.md를 훑고 후보 S 파일만 연다. active → 적용하고 ID를
        │         인용한다. provisional → 같되 잠정임을 밝힌다. 적용했는데 또
        │         교정받았나? → 반례 F를 남기고 그 S는 강등된다.
   [3] FIX      ─ 교정을 실행한다. 기록이 일을 막는 일은 없다.
   [4] CAPTURE  ─ <store>/patterns/F-<date>-<rand8>.md를 쓰고 INDEX 갱신 (+ commit).
   [5] TRIAGE   ─ 컨텍스트 건강도를 매기고 권한다 — 권고일 뿐이다: 첫 교정 → 계속 ·
        │         같은 건으로 두 번째 → 되감기 · 반복 실패 → "F-<id> 기록함.
        │         새 세션에서 그 파일만 읽고 다시 시도."
        │
   compile ─┬─ 자동: 증거 E ≥ 5 → provisional S (지금 쓸 수 있고, 밝히고 쓴다)
            └─ 수동: /ani ok <F-id>  → active S
            → F는 compiled로 닫히고, 출처는 compiled_from에 남는다
```

선제 경로도 있다. `INDEX.md`가 컨텍스트에 상주하므로 *새로운* 요청이 들어올 때마다 모든 패턴 요약과
먼저 대조된다. 요약은 "…할 때 쓴다" 형태로 적는다 — 에이전트가 올바른 스킬을 고르게 만드는 바로 그
원리다. 가장 좋은 교정은 애초에 하지 않아도 되는 교정이다.

### 신뢰 사다리

| 등급 | 올라오는 길 | 쓰이는 방식 | 내려가는 길 |
| --- | --- | --- | --- |
| **provisional** | `E ≥ 5`에서 자동으로 | 즉시. 단 active보다 뒤고, 잠정임을 밝히며 ID를 인용한다 | 반례 하나 → 심의 없이 retired |
| **active** | 사람의 승인, 또는 2세션을 버틴 provisional | 가장 먼저 적용, ID 인용 | 반례 → review-needed |
| **review-needed** | active 패턴에 반례가 걸림 | **검색에서 제외** — 틀린 매뉴얼을 다시 적용하면 안 된다 | 재승인, 또는 폐기 → retired |
| **retired** | 강등 또는 폐기 | 적용하지 않는다 | 기록으로 남는다 |

`F`는 나름의 기계를 돈다: `captured → compiled`, 아니면 `captured → archived`. 막다른 상태는 없다.

### 증거 점수 E

여기 적힌 신호만 점수가 된다. 임계값 `T`의 기본값은 5다.

| 세션 안에서 관찰된 신호 | 점수 |
| --- | --- |
| 명시적인 긍정 확인 ("그거야", "좋아") | +2 |
| 객관적 검증 통과 (초안 검사가 실제로 돌았다) | +2 |
| 세션이 끝날 때까지 그 주제로 재교정 없음 | +1 |
| 같은 부류의 패턴이 다시 등장 (2회 이상) | +2 |
| 구조 lint: S의 필수 필드가 전부 구체적이다 | 점수가 아니라 관문 |
| 같은 주제에 대한 재교정 | 이번 라운드 무효 |

침묵은 만족이 아니고 "고마워"는 예의일 수 있다. 그래서 감정보다 행동에 무게를 두고, **자동화는 잠정
등급에서 멈춘다.** *"좋은데, X는 바꿔줘"* 같이 섞인 발화는 주제별로 채점한다 — 완충 규칙은
[docs/design.ko.md](docs/design.ko.md)에 있다.

## 설계

여덟 개의 기둥, 전문은 **[docs/design.ko.md](docs/design.ko.md)**에 있다.

- **P1–P2** — 교정은 버그 리포트다. 하지만 로그 더미는 검색 잡음일 뿐이라 `F`는 `S`로
  *컴파일*되어야 한다. 사람은 게이트키퍼가 아니라 감사자다: 증거가 사용을 열고, 승인은 신뢰를
  올린다.
- **P3** — 검증은 일급 시민이다: `method / target / expected / evidence / on_failure`, 그리고
  증거는 이번 턴에 갓 나온 도구 출력이어야 한다.
- **P4–P5** — 파일이 곧 프로토콜이고, 매처는 모델이다: 정규식 코어도 임베딩도 없다.
- **P6–P8** — Tier 0은 어댑터 없이 돌아간다. 지식은 두 계층에 살면서 개인 지식은 사용자를 따라
  다니고 팀 지식은 repo와 함께 이동한다 (프로젝트만 기본으로 삼으면 되풀이되는 교정이 repo마다
  조각나고, 오버레이가 있으면 학습이 코드 리뷰의 대상이 된다). 그리고 캡처가 컨텍스트를 소모품으로
  만든다.

"검증하는 쪽은 누가 검증하나"라는 질문에도 네 겹으로 답한다.

## FAQ

**임베딩도 벡터 DB도 없는 이유는?**
저장소가 파일이면 런타임 없이도 어떤 에이전트든 — 사람이든 — 참여할 수 있다. 그리고 매처는
모델인데, "이거 예전 그 실패랑 비슷한가?"는 청크 코사인 유사도보다 모델이 이미 더 잘한다. INDEX는
설계상 컨텍스트에 들어가므로, 검색은 인프라가 아니라 그냥 읽기다.

**엉뚱한 걸 자동으로 학습하지는 않나?**
엉뚱한 걸 제안할 수는 있어도 조용히 눌러앉지는 못한다. 자동화는 잠정 등급에서 멈추고, 잠정 패턴을
쓸 때마다 그 사실과 ID를 밝히므로 보자마자 거부할 수 있으며, 반례 하나면 퇴역이다. 틀린 패턴이 낸
실패는 당신의 다음 교정으로 드러난다 — ani가 탐지하는 바로 그것이다.

**언어를 가리나?**
탐지는 "내 말을 잘못 알아들었다"는 의미에 반응한다. 어떤 언어든 상관없다. `triggers.md`가 언어별
힌트(ko/en/ja/zh/…)를 들고 있고, `config.md`에 직접 더 넣을 수도 있다.

## 프라이버시

**네트워크 호출은 한 번도 하지 않는다 — ani는 로컬 파일을 읽고 쓸 뿐, 그 외에는 아무것도 하지
않는다.** 텔레메트리도, 계정도, 본사로 보내는 신호도 없다. `bootstrap`조차 당신 디스크에 있는 세션
로그를 캘 뿐이다.
